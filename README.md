## 第二部分 · 项目内容

### 2.1 核心：角色卡

**整个项目的核心是围绕「角色卡」展开的。** 角色卡是塑造虚拟人物的核心数据载体，承载角色的身份、背景、体貌、性格、服饰、性癖、人生经历与性爱明细等结构化信息。几乎所有功能模块都以**同一套角色数据**作为上下文，实现跨模块一致、可复用的创作体验。

**角色卡的获取方式（两种）**：

| 方式 | 说明 |
|---|---|
| **AI 生成** | 按方向 / 参考灵感，由 AI 完整生成角色概要并填充全部字段（信息、服饰、配饰、体貌特征、性癖标签等），支持深化、扩充、混搭、候选方向等模式。 |
| **从小说提取** | 把已有小说文本交给 AI，自动提取出其中的角色列表及结构化数据（姓名、性别、年龄、种族、职业、性格、性爱明细等），再一键导入为角色卡。 |

角色卡支持多种性别模板（**女性 / 男性 / 扶她 / 伪娘**），每种性别按自身模板渲染全部字段；并可与**灵感角色库**（灵感板）、**世界观**模块联动，实现角色 - 世界观 - 场景的统一构建。

### 2.2 功能模块总览

软件按「区块 → 顶层模块 → 子模块 → 叶子模块」四级嵌套组织（见 `renderer/`）。功能主要由 `renderer/业务容器/` 下的各「区块」承载：

#### 🎭 区块-情欲工坊（核心内容创作）
包括：**角色台本**、**性爱台本**、**淫诗艳曲**、**浪语骚歌**、**锦绣文章**、**文学改编**、**影视动画**、**新闻媒体**、**学术春宫**、**书信社交**、**蒙学艳典**、**点评赏析**、**黄图淫册**、**黄游拔作**。
- 按不同文体 / 题材组织创作，共享统一的「题材、露骨度、意象、AI 字段」等配置，支持多档尺度（含蓄隐晦 / 唯美风雅 / 直白露骨 / 粗俗露骨）。

#### 🎨 区块-创作辅助（策划与素材）
包括：**角色卡**（核心）、**世界观**、**灵感板**、**玩法参考**、**文风分析**。
- 世界观提供多级下钻设定；灵感角色库 / 灵感板提供角色灵感收集；文风分析对文本做结构化技法拆解。

#### 📦 区块-情色杂物
包括：**记录文书**、**生活消费**、**闲情小品**、**宣传发布**。
- 围绕「杂物 / 场景 / 文案」类创作，复用同一套题材、意象与 AI 字段体系。

#### 📖 区块-情欲文学
包括：**成人小说**、**情色短章**、**系列写作**、**生活纪实**。
- 面向叙事型长 / 短篇创作，提供大纲、章节生成、正文阅读、系列关联等完整链路。

#### 🕹️ 区块-互动创作
包括：**互动小说**、**角色聊天**、**性癖问答**、**生活观赏**。
- 以「选择 → 分支」的互动叙事与模拟对话为主，可实时分支、可多角色互动。

#### 📷 声图创作
包括：**生图词典**、**生图识图**、**配音配乐**（音色库、语音合成、已生成列表）等。
- 面向图像 / 声音生成，提供 NSFW / 正常 / LoRA 分区词库，支持本地与云端生图 API。

### 2.3 语料库（参考数据）

参考语料集中存放于 `renderer/数据库/`，用于给 AI 提供风格与范例：

- **淫诗艳曲**：现代诗 / 俳句 / 打油诗 / 艳曲 / 古体诗 / 近代诗 / 淫诗 / 浪词。
- **经史子集**：经、史、子、集、蒙学等古典文本。
- **浪语骚歌**：民歌山歌 / 影视金曲 / 酒桌欢歌 / 嘻哈说唱 等。
- **文学改编**：童话改编 / 历史改编 / 神话改编 / 名著改编 / 寓言改编。
- **经典名篇**、**书信社交**、**玩法参考**（female / femboy 等）、**生图词典**（sfw / nsfw / lora）。

### 2.4 基础架构（渲染器基础区块）

`renderer/` 下另有「区块-**」作为基础层：**区块-存储 / 大模型 / 界面 / 数据 / 提示词 / 系统 / 样式 / 仪表盘 / 引擎**。其中：

- **区块-大模型**：云端与本地多提供商接入、配置管理、模型数据模板。
- **区块-提示词**：全局**提示词注册表**（`registerPrompt`）与**全局函数**（`renderPrompt`）。
- **区块-界面**：通用弹窗选择器（角色选择器 `stcdOpenCharPicker`、作品选择器 `stcdOpenWorkPicker`）、LLM 配置、用量面板。
- **区块-引擎 / 系统 / 存储**：命令、工具、本地文件系统、任务进度、用量追踪、本地读写（`LocalFS`）。

### 2.5 工程与设计原则

- **零锁定原则**：任何页面在任何状态下内容全部可见且可编辑，无前提条件；空白状态也展示可编辑表单并提供「让 AI 生成」入口。
- **AI 优先**：AI 先生成完整提案，人再修改确认；所有输入字段都应有 AI 建议入口。
- **即时保存**：输入即保存（防抖 300–500ms），无需手动点「保存」；AI 返回结果自动写入 Store；跨 Tab 读取一致。
- **云端优先**：云端大模型为主要生成引擎（充分利用大上下文与高能力），本地 LLM 为补充 / 备份。
- **二元模板**：同时满足「UI 层（AI 字段注册 + 弹窗 + 回填）」与「Prompt 结构层（提示词模板）」才算完整；不硬编码 prompt。
- **四级嵌套**：模块目录为「区块 → 顶层模块 → 子模块 → 叶子模块」严格四级相套。
- **数据落盘**：所有用户数据持久化到磁盘 `saves` 目录，不依赖浏览器缓存；本地存储（localStorage）仅用于设置类项。

```
  业务容器/          功能模块容器（情欲工坊/创作辅助/情色杂物/情欲文学/互动创作）
  数据库/            AI 生成参考语料库（部分大文件走 Git LFS）
```

## 第三部分 · 如何开始

### 3.1 环境要求

- **Node.js**（含 npm）。
- **git**。
- **Git LFS**：仓库中超过 100 MB 的大文件（如 `renderer/数据库/淫诗艳曲/📖 淫诗/淫诗.csv`）通过 **Git LFS** 管理，**克隆 / 下载需要先安装 git-lfs**。
- 云端模型 API Key（如 DeepSeek / Anthropic 等）或本地 LLM（按需配置，见软件内「大模型」区块）。

### 3.2 安装 Git LFS（每台机器一次）

```bash
# Windows（任选其一）
winget install Git.LFS
# 或官网下载 https://git-lfs.com

# macOS
brew install git-lfs

# 安装后，进入仓库运行（或在全局启用）
git lfs install
```

> 若不安装 git-lfs，克隆下来时那 170MB 的 `淫诗.csv` 只会是几 KB 的「指针」，其真实内容不会下载，依赖该语料的功能可能不完整。

### 3.3 获取源码

```bash
git clone https://github.com/2540581291/deep-narrative-engine.git
cd deep-narrative-engine
# 若 clone 时未自动拉取 LFS 大文件，补一句：
git lfs pull
```

### 3.4 安装依赖并启动

```bash
npm install
npm start
```

启动后即为 **Electron 桌面应用**。

### 3.5 快速上手：创建你的第一个角色卡

1. 打开软件，进入 **创作辅助 → 角色卡**。
2. 选择性别模板（女性 / 男性 / 扶她 / 伪娘）。
3. 点击 **「让 AI 生成」**：输入一段方向 / 设定，AI 生成角色概要并填充全部字段；或粘贴一段小说文本，选 **「从小说提取」**，自动提取角色数据并导入。
4. 在表单中自由修改、补充各字段（信息、服饰、配饰、体貌特征、性癖标签、人生经历、性爱明细等）。
5. 在其它模块（性爱台本、成人小说、互动创作等）中，将这张角色卡作为**生成上下文**，即可围绕该角色持续产出内容。

### 3.6 常见问题

- **为什么启动后报 `保存/` 为空？** 运行数据（`保存/`、`日志/`、`crash-logs/`）是运行时自动生成的，首次使用后就会出现，无需预置。
- **为什么 `npm install` 后没有 node_modules？** 是正常的——`node_modules` 被 `.gitignore` 排除，`npm install` 会重新生成。
- **LFS 大文件没下来？** 确保已安装 git-lfs 并执行 `git lfs install`，然后 `git lfs pull`。
- **没有模型可用？** 在软件「区块-大模型」里配置云端 API Key，或接入本地 LLM。
